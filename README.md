# こくものまいにち

**おかしくて、ほろり。**

some cloudsから生まれた雲のキャラクターたちの短編漫画作品集です。

- 公開先：<https://sakurak02.github.io/kokumo-comics/>
- some clouds：<https://sakurak02.github.io/some-clouds/>

HTML・CSS・JavaScriptだけで動く静的サイトです。インストールやビルドは不要です。作品一覧と個別ページは、どちらも `data/comics.json` から自動で表示されます。

## 最初の作品の画像を置く

第001話「ここくも、みつかる」（6コマ・制作状況：完成）は登録済みです。
完成画像を **`comics/001/001-1.webp`** に保存してください。画像がない間は「画像を準備しています」と表示します。代わりの絵は表示しません。画像を置けば、HTMLやJSONを変更せずに表示されます。

## 新しいおはなしを追加する

1. Procreateで漫画を完成させ、ページごとにPNGなどで書き出します。1話が1枚でも複数枚でも使えます。
2. お使いの画像変換ツールでWebPに変換し、ファイル名を「作品番号-枝番.webp」にします（例：`002-1.webp`、`002-2.webp`）。1枚だけでも必ず `-1` を付けます。文字が読める画質で保存し、縦横比は変えないでください。WebPへの変換が難しい場合はPNGのままでも使えます。
3. `comics` の中に次の番号のフォルダ（例：`002`）を作り、その中へ画像を保存します。
4. `data/comics.json` に番号・タイトル・画像パスの配列 `images` を追加します。
5. ローカルで表示を確認し、GitHubへ反映します。

例えば2作品になったときの `data/comics.json` 全体は次のとおりです。**002は記入例なので、実際の作品名に置き換えてください。**

```json
[
  {
    "number": "001",
    "title": "ここくも、みつかる",
    "images": [
      "comics/001/001-1.webp"
    ],
    "panels": 6,
    "status": "完成"
  },
  {
    "number": "002",
    "title": "新しいおはなしのタイトル",
    "images": [
      "comics/002/002-1.webp",
      "comics/002/002-2.webp",
      "comics/002/002-3.webp"
    ]
  }
]
```

- 必須項目は `number`・`title`・`images` の3つだけです。番号は `"001"` のように半角の引用符で囲み、重複させないでください。100話以降も `"100"`、1000話以降は `"1000"` と続けられます。
- 番号の大きい作品が上に並びます。JSONへの記入順は自由です。
- 作品と作品の間には半角カンマ `,` が必要です。最後の作品の後ろにカンマは付けません。括弧や引用符は半角を使います。
- 画像パスは `comics/002/002-1.webp` のように書き、先頭に `/` を付けません。フォルダ名とファイル名の作品番号を `number` に合わせ、枝番は1から始まる半角整数で付けてください。同じ話の枝番は重複させないでください。
- `panels`（コマ数）と `status`（制作状況）は任意の管理メモです。公開・非公開の設定ではありません。登録した作品はすべて一覧に表示されるため、未公開作品は公開する時点で追加してください。
- 4・6・8コマなど、コマ数によるコード変更は不要です。各ページを分割せず、縦横比を保って上から下へ表示します。個別ページの最大幅は720pxで、画像の元の幅より大きく拡大しません。
- 前のおはなしは番号の小さい作品、次のおはなしは番号の大きい作品です。該当する作品がない側のリンクは表示しません。

### 同じおはなしにページを追加する

例：第001話が3枚の場合、次の場所へ保存します。

```text
comics/001/001-1.webp
comics/001/001-2.webp
comics/001/001-3.webp
```

その作品の `images` を次のように更新します。

```json
"images": [
  "comics/001/001-1.webp",
  "comics/001/001-2.webp",
  "comics/001/001-3.webp"
]
```

- 1枚だけの話も `"images": ["comics/002/002-1.webp"]` と配列で登録します。
- 配列は枝番順に記入してください。記入順が前後しても、サイトでは枝番を数値として並べ直すため、`-2` は `-10` より先に表示されます。
- GitHub Pagesではフォルダ内の画像一覧を自動取得する仕組みを使っていません。画像を追加したら、必ず `images` 配列にもパスを追加してください。HTMLやJavaScriptの変更は不要です。
- 一覧のサムネイルには枝番が最も小さい画像（通常は `-1`）を使います。専用のサムネイル設定は不要です。
- 未配置のページには「画像を準備しています」と表示し、その後のページも引き続き表示します。
- WebPのほか、同じ命名規則のPNG・JPG・JPEGも使用できます。

任意の `alt` 項目で、個別ページの画像に読み上げ用テキストを指定できます。指定がない場合は作品番号とタイトルを使い、複数枚の場合はページ位置も付けます。

## パソコンで公開前に確認する

HTMLをダブルクリックする方法では、ブラウザの制限で作品データを読み込めません。ローカルサーバーを使ってください。

Python 3がある場合、ターミナルでこのリポジトリのフォルダに移動し、次を実行します。

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

ブラウザで <http://127.0.0.1:8000/> を開きます。第001話は <http://127.0.0.1:8000/comic.html?id=001> です。終了はターミナルで `Control + C` を押します。
Pythonがない場合は、エディターのローカルサーバー機能などでも確認できます。

確認すること：

- 一覧の番号・タイトルが正しく、新しい作品が上に並ぶ。
- 作品を選ぶと全ページが枝番順で縦に並び、文字が読める。画像の縦横比が変わっていない。
- 一覧のサムネイルに1枚目が表示される。
- スマートフォン幅でも横にはみ出さない。
- 前後のおはなしと一覧へのリンクが動く。
- 画像未配置時も「画像を準備しています」が表示される。

作品データの読み込みに失敗した場合は、JSONのカンマ・括弧・番号の重複・画像パスを確認してください。

## GitHub Pagesへ公開する

このリポジトリは **`main` ブランチの `/(root)`** を公開する設定です。設定変更やビルド操作は不要です。

1. GitHub Desktopなどで変更ファイルを確認します。画像と `data/comics.json` の両方を含めてください。
2. 変更内容をコミットします（例：`第002話を追加`）。
3. `Push origin` でGitHubの `main` へ送信します。
4. GitHubのリポジトリの「Actions」でPagesの公開処理が完了したことを確認します。反映には数分かかることがあります。
5. <https://sakurak02.github.io/kokumo-comics/> と個別ページを開いて確認します。古い表示のままならページを再読み込みしてください。

GitHubのWeb画面から画像をアップロードしてJSONを編集することもできます。その場合も保存先ブランチは `main` です。アップロード・編集の保存はそれぞれコミットになり、公開処理が始まります。

この初回制作ではコミット・プッシュ・公開操作を自動で行っていません。

## ファイル構成

```text
index.html             作品一覧
comic.html             共通の個別ページ（例：comic.html?id=001）
css/style.css          共通デザイン・画面幅への対応
js/main.js             データの読み込み・表示・前後のリンク
data/comics.json       作品情報を管理する唯一のファイル
comics/001/001-1.webp  第001話の1ページ目
comics/001/.gitkeep    空のフォルダをGitで保持するためのファイル
```

外部フォント・外部ライブラリ・解析・広告・個人情報を収集する機能はありません。some clouds本サイトのリポジトリは変更しません。
