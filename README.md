# こくものまいにち

**おかしくて、ほろり。**

some cloudsの「おはなし」と「思い出」を公開する静的サイトです。

- 公開先：<https://sakurak02.github.io/kokumo-comics/>
- some clouds：<https://sakurak02.github.io/some-clouds/>

## いつもの更新は「画像を追加 → コミット → プッシュ」だけ

JSON・Markdown・HTMLの手動作成や更新は不要です。`main`へプッシュすると、GitHub Actionsが画像のファイル名を読み取り、両コーナーの一覧を生成してGitHub Pagesへ公開します。外部ライブラリや追加サービスは使いません。

### おはなしを追加する

1. 漫画をWebPで保存します。目安は縦2400×3200pxです。
2. ファイル名を **`作品番号_タイトル.webp`** にします。例：`002_くものおさんぽ.webp`。
3. `comics/` の中に置きます。これまでと同じく作品番号のフォルダにまとめるのがおすすめです。
4. GitHub Desktopなどで画像をコミットし、`main`へプッシュします。

```text
comics/
├── 001/
│   └── 001_ここくも、みつかる.webp
└── 002/
    └── 002_くものおさんぽ.webp
```

番号は半角数字で `001`、`002`…と付けます。100話以降は `100`、1000話以降は `1000` と続けられます。一覧は番号の大きい順で、表示内容は番号とタイトルだけです。日付やコメントは表示しません。

### 思い出を追加する

1. 画像をWebPで保存します。目安は横2400×1800pxです。
2. ファイル名を **`出来事の日付_タイトル.webp`** にします。日付は半角8桁の `YYYYMMDD` です。
3. `memories/` の中に置き、コミット・プッシュします。

```text
memories/
└── 20261125_ミャクミャク空をゆく.webp
```

上の画像名は記入例で、実際の思い出画像はまだ登録していません。一覧には出来事の日付（例：2026.11.25）とタイトルだけを表示します。更新日や作品番号、コメントは表示しません。出来事の日付の新しい順で、同じ日付ではタイトル順に並びます。同じ日に複数の思い出を追加できます。

### 1話・1つの思い出に複数ページがある場合

1枚目は上の命名規則のまま、2枚目以降は**番号・日付の直後に枝番**を付け、全ページでタイトルをそろえます。

```text
comics/002/002_くものおさんぽ.webp
comics/002/002-2_くものおさんぽ.webp
comics/002/002-3_くものおさんぽ.webp

memories/20261125_ミャクミャク空をゆく.webp
memories/20261125-2_ミャクミャク空をゆく.webp
```

枝番は1から欠番なく付けてください。1枚目に `-1` を付けることもできますが、枝番なしの画像と同時に置くと重複エラーになります。ページは枝番の数値順にまとめられるので、2ページ目が10ページ目より先になります。JSONの画像配列も自動生成されます。

画像の縦横サイズは目安です。異なるサイズでも変形・切り抜きをせず、画像全体を表示します。

## サイトの表示

- タイトル「こくものまいにち」とサブタイトル「おかしくて、ほろり。」は共通です。
- 初期表示は「おはなし」。「おはなし」「思い出」のリンクで切り替えます。
- 一覧はPCで4列、タブレットで2列、スマートフォンで1列です。サムネイルを置かず、番号または日付とタイトルだけを表示します。
- 各コーナーの最新8作品を表示し、9作品目以降は「過去のおはなし」「過去の思い出」の中で8件ずつ追加します。
- 閲覧ページは1画像ずつ表示し、複数枚の場合だけ「前のページ」「次のページ」で切り替えます。
- 「前のおはなし／次のおはなし」「前の思い出／次の思い出」は別の作品へ移動します。一覧にもどると元のコーナーを表示します。
- 漫画は最大720px、横長の思い出は最大960px。スマートフォンでは端末幅に収まり、元の縦横比を保ちます。

## 初回だけ必要なGitHub Pagesの設定

以前の「Deploy from a branch / main / (root)」から、ビルド結果を公開する方式へ切り替えます。

1. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。
2. この変更一式（`.github/workflows/pages.yml`、生成プログラム、移行した画像など）を確認して `main` へコミット・プッシュします。
3. **Actions → Build and deploy Pages** が成功したことを確認します。必要なら **Run workflow** から再実行できます。
4. 公開URLで第001話と「思い出」の切り替えを確認します。

以後は画像の追加とコミット・プッシュだけで更新されます。トークンの追加や、生成データをコミットする作業は不要です。公開URLは変わりません。プルリクエストではテスト・ビルドだけを実行し、`main`へのプッシュ時に公開します。

ファイル名エラーなどでビルドに失敗すると、新しい内容は公開されず、前回成功した公開サイトが残ります。

## ファイル名に間違いがあったとき

Actionsの失敗した実行を開き、**Generate both collections from filenames** の赤いエラーを確認してください。該当するファイル名と修正内容を日本語で表示します。画像名を直して再度コミット・プッシュしてください。

エラーになる例：

- `001.webp`：アンダースコアとタイトルがありません。
- `001_タイトル.png`：WebPに変換してください。
- `20260230_タイトル.webp`：存在しない日付です。
- 同じ作品番号を違うタイトルに使用する。
- 同じ作品・同じ枝番の画像を別フォルダにも保存する。
- 1枚目と3枚目だけがあり、2枚目がない。
- タイトルの前後に空白がある。

日本語タイトルのUnicode表記の違いも確認して重複を検出します。`.DS_Store`や`.gitkeep`は一覧に入りません。

## 公開前にパソコンで確認する（任意）

Python 3がある場合、リポジトリのフォルダで次を実行します。追加インストールは不要です。

```sh
python3 scripts/build.py
python3 -m http.server 8000 --bind 127.0.0.1 --directory _site
```

<http://127.0.0.1:8000/> を開いて確認します。サーバーの終了は `Control + C`。画像の追加・変更後はもう一度ビルドして再読み込みしてください。HTMLのダブルクリックや、ソースフォルダの直接配信では生成データを読み込めません。

テストは次のコマンドです。

```sh
python3 -m unittest discover -s tests -v
```

## 移行とURLの互換性

移行前は第001話「ここくも、みつかる」が1作品ありました。画像はファイル名からタイトルを読み取れるように変更しましたが、画像データそのものは変更していません。タイトルも維持しています。

- 新しい保存場所：`comics/001/001_ここくも、みつかる.webp`
- 既存の閲覧URL：`comic.html?id=001` を維持
- 既存の画像URL：`comics/001/001-1.webp` もビルド時に同じ画像をコピーして維持
- 既存の `data/comics.json` のURLは維持し、公開先で自動生成（ソースの手動管理ファイルは廃止）

おはなしのURLは作品番号が同じならタイトルを変えても変わりません。思い出のURLは日付とタイトルから決まるため、公開後にそのどちらかを変更するとURLが変わります。

## 構成

```text
index.html                  共通の一覧・コーナー切り替え
comic.html                  共通の閲覧ページ
css/style.css               共通デザイン
js/main.js                  両コーナー共通の表示・ページめくり
comics/                     おはなしの画像
memories/                   思い出の画像
scripts/build.py            両コーナー共通の生成プログラム
tests/test_build.py         ファイル名・重複・日付・移行互換性の検証
.github/workflows/pages.yml 自動テスト・ビルド・公開
_site/                      自動生成された公開ファイル（Git管理対象外）
  data/comics.json           おはなし一覧（自動生成）
  data/memories.json         思い出一覧（自動生成）
```

解析・広告・個人情報を収集する機能はありません。some clouds本サイトのリポジトリは変更しません。
